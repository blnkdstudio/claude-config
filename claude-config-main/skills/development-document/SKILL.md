# /development document

You are the **Development Orchestrator**. Run the post-implementation documentation suite for a completed feature.

The feature folder path is provided as an argument (e.g., `wiki/implementation/user-invitation-system`).

---

## Step 1: Load Context

1. Read `wiki/knowledge/knowledge.md` — the project knowledge base
2. Read `{feature-folder}/implementation-guide.md` — verify status is "Implemented"
3. Read `{feature-folder}/api-contract.md` — current API contract from planning phase
4. Read `{feature-folder}/ui-consumption-guide.md` — current UI guide from planning phase

If the implementation guide status is not "Implemented", warn the user:
- "This feature hasn't been implemented yet. Run `/development implement` first, or pass `--force` to document anyway."

---

## Step 2: Parallel Documentation Agents

Launch **3 agents in parallel** (in a single message with multiple Agent tool calls) to generate all documentation concurrently. These agents work on independent output files with no overlap.

| Agent | Task | Output |
|-------|------|--------|
| **process-cartographer** | Feature flow tracing (Step 2a) | `{feature-folder}/feature-flow.md` |
| **backend-expert** | Swagger sync + API/UI contract sync + env/error catalog (Steps 2b + 2c) | Controller files, `api-contract.md`, `ui-consumption-guide.md`, `.env.example`, `wiki/error-catalog.md` |
| **technical-lead** | Project-level docs + knowledge base refresh (Steps 2d + 2e) | `CLAUDE.md`, `CHANGELOG.md`, `wiki/knowledge/knowledge.md` |

### Step 2a: Feature Flow Documentation (process-cartographer)

Prompt the **process-cartographer** agent to:
- Trace the feature's complete execution flow end-to-end (entry points → services → database → response)
- Document all code paths, including error handling and edge cases
- Map interactions with other modules
- Identify queue/event flows if applicable

Write the output to `{feature-folder}/feature-flow.md` using this structure:


### Step 2b: Swagger, API & Environment Sync (backend-expert)

Prompt the **backend-expert** agent with all of the following tasks in a single prompt (the agent handles them sequentially within its own execution):

1. **Swagger/OpenAPI decorators** — Review all controllers touched by this feature and ensure:
   - All endpoints have `@ApiOperation()` with a summary and description
   - All DTOs have `@ApiProperty()` on every field with type, description, and example
   - Response types are documented with `@ApiResponse()` for success and error cases
   - Any query params or path params have `@ApiParam()` / `@ApiQuery()`
   - Tags are applied via `@ApiTags()` for logical grouping

2. **API contract sync** — Compare the actual implemented endpoints against `{feature-folder}/api-contract.md`:
   - Update request/response shapes if they changed during implementation
   - Add any new error codes that were introduced
   - Update status codes if they differ from the plan
   - Mark the file as "Verified against implementation on [date]"

3. **UI consumption guide sync** — Compare actual implementation against `{feature-folder}/ui-consumption-guide.md`:
   - Update endpoint paths, methods, or payloads if they changed
   - Update error states and codes if they changed
   - Add any new flows that emerged during implementation
   - Mark the file as "Verified against implementation on [date]"

4. **`.env.example` sync** — Scan all new/modified files for environment variable usage (`process.env.*`, `ConfigService.get(...)`, etc.):
   - Add any new variables to `.env.example` with descriptive comments and placeholder values
   - Remove any variables that are no longer used
   - Ensure variable grouping and ordering is consistent

5. **Error catalog update** — If the project has an error catalog (`wiki/error-catalog.md`), update it:
   - Add all new error codes introduced by this feature
   - Include HTTP status, error code string, human-readable message, and when it occurs
   - If no error catalog exists yet, create `wiki/error-catalog.md` with all known error codes from the feature

---

### Step 2d: Project-Level Documentation & Knowledge Base (technical-lead)

Prompt the **technical-lead** agent with all of the following tasks in a single prompt:

1. **CLAUDE.md update** — Review and update if the feature added:
   - New modules → add to the Modules section
   - New routes → add to the API Surface / route descriptions
   - New queues or job types → add to the Background Processing section
   - New environment variables → add to the Key Environment Variables section
   - New commands or scripts → add to the Commands section

2. **Deprecation notices** — If this feature replaces or changes existing behavior:
   - Add deprecation comments in the code (`@deprecated` or `// DEPRECATED:`)
   - Document deprecated endpoints/features in `{feature-folder}/api-contract.md` under a Deprecations section
   - If applicable, note the removal timeline

3. **Changelog entry** — If a `CHANGELOG.md` exists in the project root, add an entry under the appropriate version/date section. If not, skip this step (do not create a changelog).

4. **Knowledge base refresh** — Re-read the codebase and update `wiki/knowledge/knowledge.md` to reflect the new feature. Preserve any manual annotations. Update the generation date.

---

## Step 3: Collect Results

Wait for all 3 agents to complete. Collect their outputs and any issues reported.

---
