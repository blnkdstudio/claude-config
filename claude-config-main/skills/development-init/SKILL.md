# /development init

You are the **Development Orchestrator**. Perform a full codebase initialization to create the shared knowledge file at `wiki/knowledge/knowledge.md`.

## Step 1: Deep Codebase Discovery

Analyze the entire codebase systematically using **parallel sub-agents** to minimize wall-clock time. Read actual files — do not guess or assume.

### Step 1a: Quick Scan (orchestrator)

Before launching agents, do a quick scan yourself to establish baseline context:
1. Read `package.json` (or equivalent) for project name, dependencies, and scripts
2. Run `ls` on the project root and `src/` (or equivalent) to understand the directory layout
3. Detect the tech stack (language, framework, database, test framework) from config files

This gives you enough context to write effective agent prompts.

### Step 1b: Parallel Agent Discovery

Launch **3 agents in parallel** (in a single message with multiple Agent tool calls), each focused on a domain:

| Agent | Domain | What to Discover |
|-------|--------|-----------------|
| **backend-expert** | Application & API | Architecture (app type, module structure, entry points, DI pattern, middleware/guards). API surface (all route prefixes, module owners, auth methods, authorization pattern, versioning). External integrations (third-party APIs, SDKs, webhook handlers, email/SMS/push services). |
| **database-expert** | Data & Infrastructure | Database engines, ORM/query builder, schema/model locations, naming conventions, migration tool and history. Caching layer (Redis, in-memory). File/object storage (S3, local). Background processing (queue system, queue names, job types, processor locations, cron jobs, WebSocket features). DevOps (Docker setup, CI/CD pipeline, env var patterns, deployment target). |
| **technical-lead** | Quality & Conventions | Tech stack versions (language, runtime, framework, all major deps). Testing setup (framework, file naming convention, config location, test utilities/factories/fixtures, coverage config). Code conventions (linter/formatter config, TypeScript strictness, naming conventions, import style). Key commands (build, dev, test, lint, format, migration, docker, custom scripts). Project identity (name, description, purpose, repo URL, branch strategy). |

Each agent prompt should include:
- The baseline context from Step 1a (so agents don't re-read the same config files)
- Instruction: "Read actual source files. Do not guess. Report `[UNRESOLVED]` for anything you cannot locate."
- Instruction: "Return your findings in structured markdown sections with tables where appropriate."

### Step 1c: Collect & Merge Results

Wait for all 3 agents to complete. Merge their findings into the unified knowledge file structure in Step 2. If any agent reports `[UNRESOLVED]` items, include them in the summary for the user's attention.
